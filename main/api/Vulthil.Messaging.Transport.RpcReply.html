Class RpcReply

Namespace
Vulthil.Messaging.Transport
Assembly
Vulthil.Messaging.dll

The request/reply wire contract every transport shares. A reply is a MessageEnvelope that echoes the request id the requester correlates on and the request's business correlation id. On success it carries the response payload at the response type's URN; on failure it carries an RpcFault at UrnUri. Transports build replies with Success<TResponse>(TResponse, IMessageConfigurationProvider, string?, string?), Fault(Exception, IMessageConfigurationProvider, string?, string?) and ShortCircuited(IMessageConfigurationProvider, string?, string?), and read them with ToResult<TResponse>(MessageEnvelope, IMessageConfigurationProvider), so a reply means the same on every transport.

ToResult<TResponse>(MessageEnvelope, IMessageConfigurationProvider)

Reads reply as the outcome of a request for TResponse. The response payload becomes a success. An RpcFault becomes a Failure failure that carries the remote message. A reply of any other type, a null payload, or a payload that cannot be read becomes a Deserialize failure; a malformed reply never throws.
