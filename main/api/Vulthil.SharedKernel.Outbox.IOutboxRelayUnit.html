ClaimAsync(int, int, CancellationToken)

Claims up to batchSize pending messages, oldest first: messages that are neither processed nor dead-lettered and whose retry count is below maxRetries. A store with row locking claims rows that no concurrent relay unit can claim until this unit's transaction ends.

RecordAsync(IReadOnlyList<Guid>, IReadOnlyList<OutboxMessageFailure>, int, CancellationToken)

Records the outcomes of claimed messages: each message in relayedIds is marked processed, and each failure records its error and increments the message's retry count. A failure that brings the retry count to maxRetries dead-letters the message.

RunStepAsync(Func<CancellationToken, Task>, CancellationToken)

Runs the dispatch of one claimed message as a step of this unit, for a dispatch that shares the relay's scope and so the unit's transaction. When step completes, the store saves the changes the step left pending, so they commit with the batch. When the step or that save throws, the store undoes the step's work without ending the unit's transaction — it rolls back to a savepoint where the provider supports one, and forgets the step's tracked changes — and then rethrows, so the unit can still record the outcomes of the batch.
